Redis
- stands for Remote dictionary server

Use cases of Redis:
- Cache
- database
- session storage
- message broker
- real-time data store
- pub/sub system
- distributed lock system/manager
- leader election
- rate limiter

Redis keeps data primarily in memory, which allows for extremely fast read and write operations compared to traditional disk-based databases.
Traditional databases like MySQL, PostgreSQL, MongoDB are generally designed around persistent storage.


For example:
- Imagine an e-commerce application with:
10,000 request/second

- if a large percentage of those requests might repeatedly ask for same information (e.g., product details), hitting the database every time can become a bottleneck.

Without caching:
10,000 requests hit the database per second

With caching (e.g., using Redis):
- Frequently requested data is stored in the cache
- Only cache misses hit the database
- Reduces load on the database and improves response time


1. Check Redis
2. If data exists -> return it
3. If data does not exist -> fetch from database and store in Redis
4. Return the data to the client

This is known as Cache-Aside pattern.
